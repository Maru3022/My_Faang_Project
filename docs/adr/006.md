# ADR-006: Account slice — identity mapping, profile and legal acceptance

Status: accepted.

## Context
Phase 1 delivered the foundation; the documented next vertical slice is mapping a managed OIDC identity to an internal user, serving `/me`, and adding legal acceptance versioning before curriculum.

## Decision
- New `identity-access` module maps an `(issuer, subject)` pair to an internal `UserId`, durably stored in `identity.identity_mapping` with a `(provider, subject)` primary key. Resolution is find-or-create and idempotent; a `UserRegisteredV1` event is published on first mapping.
- `user-profile` now owns persistence (JDBC adapter, not JPA) behind a `UserProfileRepository` port. Reads and writes go through a `UserProfileFacade` whose contract lives in the module root package. Profile writes use optimistic concurrency on `version`.
- New `legal` module tracks accepted versions of `PRIVACY_POLICY` and `TERMS_OF_SERVICE`, seeded in migration 002. Accepting a non-current version is rejected with a conflict.
- The identity is always taken from the verified JWT claims (`iss`/`sub`) via a `CurrentUser` resolver; never from a request body.
- Domain failures are raised as `DomainException` (shared-kernel) with a stable `code` and an HTTP-independent `DomainErrorStatus`, mapped to Problem Details in the app's exception handler.

## Alternatives considered
- Event-driven profile creation via a listener instead of a synchronous `ensureProfile` in the request path. Rejected for now: Spring Modulith only delivers events to `@ApplicationModuleListener`, and async delivery would make request completion depend on event timing. `ensureProfile` is idempotent and the durable event is still published, so a later consumer can react without changing behaviour.

## Consequences
- `shared-kernel` gained `DomainException`/`DomainErrorStatus`; it remains free of web framework dependencies.
- The `kotlin-allopen` (Spring) plugin is now applied to all subprojects so `@Service`/`@Repository`/`@Component` classes can be proxied by CGLIB.
- Module public contracts live in each module's root package; Modulith exposes the root package by default and verifies boundaries.
- API additions: `GET/PATCH /api/v1/me`, `GET/PUT /api/v1/legal/acceptances`. Ownership and input validation are enforced; unauthorised access yields Problem Details with a `code`.
